# BookVault AI 协作规则

> 精简版硬规则在根目录 `AGENTS.md`（每次会话自动加载）；本 skill 是可照着执行的详细工作流。

## 1. 标准任务流程

1. **理解**：用一句话重述任务目标；有不确定的点先列出来。
2. **查现状**：`git status` + 相关文件 + 现有测试；仓库实态与任务描述不符时，先报告再动手。
3. **定方案**：
   - 小改动（≤3 个文件、无公共接口变更、无新依赖）→ 直接实现。
   - 其余 → 先给计划（改哪些文件、接口边界、验收标准），等用户确认。
4. **实现**：代码遵守 `bookvault-dev-standards`，界面遵守 `bookvault-ui-style`；一次只围绕一个可验证目标。
5. **验证**：运行与改动相关的测试和 lint；格式解析类改动用 `samples/` 真实样本验证。
6. **汇报**：按 §3 模板输出。

## 2. 必须暂停等用户确认的场景

- 删除文件 / 数据、重置数据库、覆盖任何已存在的配置。
- 引入新依赖（即使通过 dev-standards §4 检查单，也要报备五项结论）。
- 数据库 schema 破坏性变更（删列 / 改类型 / 弃表）。
- 触及需求文档 §12「已确认」清单中的产品方向。
- 涉及私密内容同步策略、加密、凭据存储的设计。
- 任何不可逆命令。

## 3. 结束汇报模板（每次任务结束按此结构输出）

对应需求文档 §11.12「说明未完成项」：

```markdown
## 改动
- <文件/模块 + 一句话说明>

## 验证
- <跑了什么测试 / lint，真实结果如何；没跑的写明"未验证 + 原因">

## 未完成与限制
- <未覆盖的场景、已知问题>

## 风险与下一步建议
- <可选>
```

## 4. 红线（违反即返工）

- 未实现的功能 / 格式不得宣称「已支持」。
- 测试失败不得说「完成」；跳过的测试必须说明原因。
- 不提交密钥、凭据、私密样本文件。
- 不伪造样本测试通过的结论；兼容性结论必须来自真实样本运行结果。
