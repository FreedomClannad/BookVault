## 3. EPUB 分页/竖排适配（未开始，包 A 收尾）

- 现状：EpubReader 为 iframe srcdoc 渲染（ADR-002），仍是滚动模式。
- 做法：iframe 内注入多列 CSS（同 TxtReader 引擎的量测/平移方案），屏数与页码状态跨 iframe 边界上提到 Reader 层；注意 iframe 内键盘不冒泡的历史限制。
- 验收标准：EPUB 分页/竖排/翻页动画与 TXT 行为一致；改排版不重载文档、不丢位置。

## 4. 明确不移植（决策记录，勿反复评估）

- **振动/触觉反馈**：桌面无振动硬件。
- **循环轮播书架**：~~手机交互形态，桌面 3D 书柜已是更合适形态~~ **决策反转（2026-10-25，负责人指示）**：立体书架按「发现」页演示形态移植（中心封面 + 书脊透视陈列 + 翻页器，`BookCarousel`），原分类分柜横排 3D 书（Book3D）退为批量整理/多选时的网格形态。
- **edge-tts 在线音色**：云依赖 + 隐私顾虑，用系统 TTS 替代。
- **曲面纸页翻动**：需 canvas/WebGL，成本一顶三；若将来要做放最后，可选。

## 5. 已交付部分的已知限制（包 A `9b61aba` / 包 B 2026-10-25）

包 A（阅读器交互）：

- 竖排 + 对页不支持：实测 Chromium/WebView2 的 vertical-rl 多列分片沿纵轴向下堆叠（与 CSS 多列规范不符），竖排分页按实测行为实现（`TxtReader.tsx` 文件头有契约注释）；排版面板在竖排下隐藏「版式」项。若未来引擎改回规范行为需同步调整。
- 滚动模式小说：PgUp/PgDn 保留浏览器默认滚动；阅读中切到「滚动」模式会回到章首（进度已落库，重进书籍可恢复）。
- 自动阅读定时间隔在每次翻页后重新计时（「每页 N 秒」语义）；滚动模式按 `900/autoSec` px/s 匀速滚动。
- EPUB 仍为滚动模式（§3）。
- 交互逻辑已在浏览器 mock 模式实测通过；**Tauri 真窗口（WebView2）未人工验证**。

包 B（书架与查找）：

- 立体书架为循环书池静态渲染（count + 2×edgeSlots 个档位）：数千本以上的超大书库首渲染节点较多，Phase 1 个人书库量级无感知；提取波/投影常数与原作一致，面片为 CSS matrix 仿射（与原作斜二测投影同一数学）；书体尺寸随容器宽度自适应（cover 112–160px）。
- 原 3D 书组件（Book3D）已由立体书架 + 模块网格取代并删除；封面兜底逻辑在 `coverFallback.ts`，网格封面字节走会话级缓存。
- 立体书架的键盘 ←/→ 与回车仅在立体模式挂载时生效；批量整理下立体形态让位给平铺网格（多选需要总览）。
- 查找定位按「章内字符比例」换算（滚动位置/分页屏号），对图片占位多、排版特殊的章节是近似定位。
- EPUB 命中只滚动定位，**iframe 内不做命中词高亮**（TXT 有 mark 高亮）；PDF 查找后置未做。
- 整书检索逐章串行拉取，超大书库书籍首搜有明显等待（面板显示 x/y 章进度）；每章命中上限 20、总量 300。
- 本地删除作品**不同步删除 NAS 侧内容**（同步删除属 P1 冲突策略范畴），重推时若 NAS 无此书则一致，已有内容留在 NAS。
- 批量改分类逐本串行调用（本地 SQLite，量级无感知）。

2026-10-25 导入链路修复（用户真机反馈）：

- **拖拽导入接通**：Tauri v2 默认接管 webview 拖放（wry `drag_drop_handler` 消费事件），HTML5 `dataTransfer.files` 在桌面端收不到文件路径——原 `onDrop` 实现从未生效。现改走 `getCurrentWebview().onDragDropEvent()`（`App.tsx`），drop 事件全局生效（书架与阅读中均可拖入）。
- **目录导入展开**：`Library::expand_import_paths`（含单测）——图片文件夹仍整体作为一本漫画；其余目录递归收集 epub/txt/pdf/cbz/zip（深度 ≤8，跳过隐藏目录与符号链接），此前非图片目录直接报「不支持」。
- **导入按文件聚合结果**：`import_paths` 返回 `ImportBatch{imported, failed}`，坏文件不再让整批失败；toast 报成功/重复/失败计数与首条错误。
- **探测层修复**（`detect.rs` + `tests/detect_edge.rs`，真实样本探针验证）：UTF-16 BOM 的 TXT（Windows 阅读器导出常见）不再被当二进制拒绝；PDF 允许头部 1KB 内垃圾前缀（lopdf 实测可解析）；zip 系按条目名区分 EPUB（mimetype/.opf/container.xml）与 CBZ，非两者拒绝——修复 mimetype 被压缩的 EPUB 被静默导入为 0 页 CBZ 的问题。
- 遗留限制：UTF-16 仅支持带 BOM（无 BOM 仍拒绝）；图片文件夹扫描仍为根目录+一层子目录（更深嵌套不支持，原计划 §5 M1.6 语义未变）；删除仍只删本地、不动 NAS。
