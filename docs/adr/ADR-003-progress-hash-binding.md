# ADR-003：阅读进度绑定内容哈希（sha256）

- 状态：✅ 已采纳（2026-10-24）
- 关联：需求 §5.3/§7.1、Phase 1 计划 §4.4 不变量 1

## 背景

阅读位置（章节+进度 / 页码 / 图片索引）必须能对抗源文件变化：同一书架条目被替换为新版本文件后，旧进度若直接沿用会定位错乱。

## 决策

1. `reading_progress` 行携带 `content_sha256`，必须等于关联 `book_files.sha256`（进度绑定文件版本，而非绑定书架条目）。
2. 打开书籍时校验：哈希一致 → 恢复进度；失配 → **显式降级**：提示「文件已变更」，用户选择保留旧进度（不可用则重置），绝不静默沿用。
3. 解析产出必须携带 `parserInfo { parser, version }` 与源哈希（`bv-formats` 接口约定），便于诊断与迁移。

## 理由

需求 §5.3 明确要求进度关联文件版本；哈希是文件身份的最小可靠表达，且导入去重（§4.4 不变量 2）本就需要 sha256。

## 后果

- 同一 Edition 下换文件（例如重新导出的 EPUB）不自动迁移进度；按章节 ID 迁移列为 P1 优化。
- 哈希计算在导入时一次完成并入库，阅读路径无额外开销。
