# ADR-008：同步游标与冲突保留

- 状态：✅ 已实现（M3/M4）
- 关联：需求 §7.1/§7.2、Phase 1 计划 §4.4 不变量 3

## 决策

1. **变更流**：服务端所有写操作（work/edition/file/progress upsert）追加 `change_log`
   （自增 `seq` 单调）；客户端 `GET /sync/changes?cursor=N` 增量拉取，`POST /sync/ack` 记录
   已应用位点。服务端序号是权威（不信任客户端时钟，需求 §7.2）。
2. **幂等**：所有变更应用为 upsert，重放安全；游标只前进。
3. **进度冲突**：服务端按 `(device_id, file_id)` 存每设备一行（保留双方，不覆盖）；
   桌面端本地同样按设备保留，拉取时应用其他设备行，展示取 `updated_at` 最新。
4. **断网**：客户端任何请求失败即报错返回，本地库不动（恢复后重试）。

## 理由

- 双设备阅读同一本书的进度「物理上不冲突」（各有各的行），UI 合并视图取最新即可；
  真正的语义冲突（两端都改了同一文件的进度）保留双方数据，由用户在 UI 上选，
  不静默丢弃（需求 §7.2）。
- e2e 验证：`apps/desktop/src-tauri/tests/sync_e2e.rs`（双设备进度一致 + 断网安全）。

## 已知限制 / P1

- 大文件下载整文件（无断点续传 UI）；上传无取消；`sync/ack` 暂只记录位点不裁剪日志。
