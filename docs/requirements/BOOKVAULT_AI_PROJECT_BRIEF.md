# BookVault --- AI 项目开发说明

> 本文档是 BookVault 项目的核心需求与架构约定，供 AI
> 编程助手、代码代理和后续开发者作为长期上下文使用。
>
> 文档状态：初始规划稿（尚非已实现功能清单）。技术选型和接口细节可在验证后调整，但不得擅自改变已确认的产品方向。

## 1. 项目概述

### 1.1 项目名称

- 项目名：**BookVault**
- 产品类型：个人小说与漫画阅读器，配套自托管 NAS 服务端
- 目标：支持桌面端、移动端和家庭 NAS；管理本地与 NAS
  书库；在授权来源范围内导入内容；同步书目、阅读进度和用户设置。

### 1.2 产品定位

BookVault 是一个以个人书库为中心的跨平台阅读系统：

- **桌面端**：完整阅读和书库功能，并提供桌面专属隐私功能，包括快捷隐藏、私密书架、可配置的中性/模拟工作界面、内容导入与刮削管理。
- **移动端**：专注阅读、书架、搜索、离线缓存和同步，不要求复刻桌面端的快速隐藏、模拟终端等功能。
- **NAS
  服务端**：由用户自行部署，管理中心书库、元数据、设备授权、同步状态和文件存储。
- **局域网优先**：第一阶段只支持家庭局域网同步；架构应避免将来增加安全远程访问时需要重写核心业务。
- **混合存储**：NAS
  是中心书库，同时允许各设备导入和保存本地文件。用户可选择仅存
  NAS、仅存本地或两边保存。
- **离线可用**：NAS
  不可用时，设备已缓存/下载的书籍仍应能阅读；恢复连接后再同步。

### 1.3 产品原则

1.  阅读是基础价值，NAS 同步和隐私体验是重要特色。
2.  本地阅读不应依赖 NAS 在线。
3.  原始书籍文件应尽量保留；转换是可选处理，不得默认破坏或替换原件。
4.  小说和漫画使用统一书库模型，但允许不同的阅读位置模型与渲染实现。
5.  格式解析、内容来源、元数据刮削、书库、同步和 UI 必须分层。
6.  在线导入仅支持用户有权访问和下载的来源，不实现 DRM
    破解或绕过访问控制。
7.  先实现稳定的本地阅读与 NAS
    同步闭环，再增加复杂来源、转换和自动化能力。

## 2. 产品端与职责

### 2.1 桌面客户端

主要能力： - 小说与漫画阅读。 - 本地文件导入和本地书库管理。 - NAS
书库浏览、文件上传/下载和同步状态查看。 -
私密书架、独立解锁和隐私选项。 -
快捷键快速隐藏、快速切换窗口/预设界面。 -
可配置的中性工作界面或模拟终端，显示预设演示输出或用户明确选择的真实日志。 -
元数据刮削、在线来源配置、导入任务管理。 -
阅读主题、字体、排版和漫画翻页/滚动设置。

隐私要求： - 快速隐藏只是一种视觉隐私功能，不等于文件加密。 -
尽可能避免私密书名出现在窗口标题、系统通知、最近打开列表、任务栏/Dock
预览和普通搜索结果中。 - 私密书架与普通书架在
UI、索引和同步策略上应明确区分。 -
私密内容默认不得无提示地同步到所有设备；必须提供可理解的同步策略。 -
若实现文件加密，应说明密钥保管、恢复和忘记密码的后果，不得声称"加密"却只隐藏
UI。

### 2.2 移动客户端

主要能力： - 小说与漫画阅读。 -
书架、搜索、分类、历史记录、书签和阅读进度。 -
本地文件导入、离线缓存。 - 连接家庭 NAS 后同步。 -
网络不可用时使用本地文件和缓存。 -
不要求实现桌面专属的模拟工作界面、全局快捷隐藏等功能。

移动系统可能限制后台局域网扫描和后台任务。产品可以在应用启动、回到前台、网络状态变化或系统允许的后台任务时触发同步，但不得承诺
iOS/Android 上无限制、持续的后台同步。

### 2.3 NAS 服务端

主要职责： - 设备配对、认证、撤销和授权。 -
中心书库索引、元数据、分类与作品/文件关系。 -
文件上传、下载、校验、范围读取与断点续传。 -
同步变更记录、游标和冲突处理。 - 导入任务队列与任务状态。 -
元数据刮削和格式转换任务（作为后台可选任务）。 -
备份、恢复和运行状态诊断。

NAS
服务端不得成为所有阅读请求的必经路径。客户端应能直接读取已经保存到本地的文件。

## 4. 总体架构

推荐按职责分层：

1.  **客户端 UI 层**：书架、阅读页面、设置、隐私模式和导入任务界面。
2.  **应用业务层**：书库用例、阅读状态、导入工作流、设备同步协调。
3.  **格式适配层**：识别文件格式，解析元数据、目录、页面与资源。
4.  **本地数据层**：SQLite 元数据/进度数据库、原始文件、缓存、同步队列。
5.  **服务端 API 层**：认证、书库、资源、导入任务和同步接口。
6.  **服务端任务层**：刮削、下载、格式转换、批量扫描和重试。
7.  **NAS 持久化层**：文件目录、SQLite 数据库、任务状态与备份。

模块间通过明确接口通信。不要让 UI 直接调用具体格式解析库、网站抓取逻辑或
SQL 查询。

## 5. 格式适配架构

### 5.1 基本原则

- 根据文件签名、扩展名、MIME
  类型和实际内容综合识别格式，不能只信任扩展名。
- 每种格式通过独立适配器实现；适配器输出统一的元数据、目录、资源和阅读位置。
- 保留原始文件；转换文件作为可追踪的衍生物。
- 对大型文件优先流式/按需读取，避免将整本书或整个压缩包无条件载入内存。
- 阅读组件不直接依赖具体文件格式；平台渲染和交互与格式解析分离。
- 记录解析器名称/版本、源文件哈希和转换信息，便于诊断和迁移。

### 5.2 格式规划

---

格式/类型 优先级 建议处理方式

---

EPUB P0 解析目录、正文、CSS、图片、字体和元数据

TXT P0 编码识别、中文乱码处理、章节切分和长文本处理

PDF P0 分页阅读、缩放、目录；扫描 PDF
作为页面图像处理

CBZ / ZIP P0 图片排序、封面识别、页面索引、按需读取

图片文件夹 P0 支持常见图片、自然排序、可选手动排序

MOBI / AZW / AZW3 P1 先验证无 DRM
文件；可直接解析或使用受控转换流程

FB2 / FB2.ZIP P1 提取正文、章节、元数据与图片

HTML / XHTML / Markdown P1/P2 清理危险脚本，处理图片与相对资源

CBR P1 通过经过验证的 RAR 读取库或隔离工具处理

CB7 / 7z P1/P2 通过兼容的 7z 组件处理

DOCX / RTF P2 可选转换为内部阅读格式或 EPUB

DjVu / XPS / CHM 等 P2 按真实需求接入解析器或转换工具
----------------------------------------------------------------------------------------------

P0/P1/P2
表示开发优先级，不代表已有实现或承诺百分百兼容。格式覆盖应通过真实样本测试验收。

### 5.3 统一解析器接口草案

以下仅用于表达边界，实际实现需补齐错误类型、取消任务、资源生命周期和流式读取设计：

```ts
type BookKind = "novel" | "comic" | "document";

type BookMetadata = {
  title?: string;
  authors: string[];
  description?: string;
  language?: string;
  cover?: ResourceRef;
  identifiers: Record<string, string>;
};

type ReadingLocation =
  | { type: "chapter"; chapterId: string; progress: number; anchor?: string }
  | { type: "page"; pageIndex: number }
  | { type: "comic"; chapterId?: string; imageIndex: number };

interface BookParser {
  detect(input: FileInput): Promise<number>;
  readMetadata(input: FileInput): Promise<BookMetadata>;
  readContents(input: FileInput): Promise<BookContents>;
  getResource(ref: ResourceRef): Promise<ResourceData>;
}
```

注意： - 小说进度需要章节 ID 与章节内位置；漫画需要页码/图片索引。 -
进度必须关联书籍文件版本或内容哈希，避免源文件变化后定位错乱。 - PDF
可以采用页码模型；不同阅读器可以提供不同的视觉呈现。 -
不要把所有格式强行转换成一种格式后才允许阅读。

## 6. 导入与刮削架构

### 6.1 统一导入流水线

所有来源都进入统一的导入任务流程：

1.  用户选择来源并创建任务。
2.  来源适配器验证来源和授权，获取元数据或文件。
3.  将文件下载/复制到隔离的暂存区。
4.  检查文件签名、大小、哈希、压缩包结构和安全限制。
5.  调用格式适配器解析元数据和目录。
6.  使用元数据提供器匹配标题、作者、封面、简介、系列等。
7.  展示候选结果，允许用户确认或修改。
8.  检测重复作品/文件，决定新增版本、关联现有作品或跳过。
9.  将原始文件、元数据和索引正式入库。
10. 生成同步变更，按用户策略分发到其他设备。
11. 记录结果、错误原因和可重试状态。

导入必须是可恢复的后台任务，不应阻塞阅读
UI。应支持取消、重试、进度查询和错误诊断。

### 6.2 来源适配器

建议使用可插拔来源接口：

- `LocalFileAdapter`（P0）：导入电脑或手机文件。
- `NasFolderAdapter`（P0）：扫描用户授权的 NAS 目录。
- `DirectUrlAdapter`（P1）：从允许访问的文件直链下载
  EPUB、PDF、漫画压缩包等。
- `OpdsAdapter`（P1）：浏览、搜索和获取符合 OPDS 规范的内容。
- `WebsiteProvider`（P2）：为具体、允许访问的网站实现独立适配器；网站结构变化不得影响核心导入流程。

每个来源应描述自己的能力，例如是否支持搜索、分页、元数据、正文下载、增量更新和认证。不要假设所有网站都能通过同一种抓取方式工作。

### 6.3 元数据刮削器与正文获取器分离

`MetadataProvider`： - 按书名、作者、ISBN、来源 ID 等搜索候选作品。 -
返回标题、作者、封面、简介、语言、标签、系列和外部标识。 -
记录字段来源和更新时间。 -
支持多个提供器匹配；不确定时让用户确认，不能仅按标题自动覆盖。

`ContentProvider`： - 获取用户有权访问的书籍文件或章节。 -
记录来源、作品 ID、下载时间、文件哈希和任务状态。 -
支持限速、超时、重试、取消和断点续传。 -
下载完成后仍要做文件验证和格式识别。

元数据更新不应触发完整文件重新下载。封面、简介、书籍文件和章节内容应可独立更新。

### 6.4 示例导入请求

这是概念性 API 结构，实际实现需补充权限、校验和错误响应：

```json
{
  "sourceType": "direct_url",
  "source": {
    "url": "https://example.org/books/sample.epub"
  },
  "options": {
    "fetchMetadata": true,
    "downloadContent": true,
    "targetLibrary": "default"
  }
}
```

不要把密码、Cookie、Token 或其他秘密直接写入普通任务
JSON、日志或数据库明文。需要登录的来源应使用安全凭据存储，并明确告知用户授权范围。

## 7. NAS 中心书库、设备本地文件与同步

### 7.1 数据归属

---

数据 建议权威来源 规则

---

作品元数据、分类和书架组织 NAS 使用版本号/变更序号，防止旧数据覆盖新数据
为中心，可允许客户端提出变更

阅读进度和书签 多设备共同产生 记录设备与变更时间；采用专门合并策略

原始书籍文件 文件实体/版本有明确身份 使用哈希校验；冲突时保留副本或要求用户确认

设备缓存 设备本地 可清理，不得误删 NAS 原文件

私密内容 由用户明确选择同步范围 默认不无提示地复制到所有设备
--------------------------------------------------------------------------------------------------------

### 7.2 同步策略

- 阅读进度和书签优先同步。
- 元数据、分类和书架结构按变更增量同步。
- 大文件按需下载；允许用户标记"离线可用"。
- 文件传输支持哈希校验、分块/范围请求、断点续传和取消。
- 维护每台设备的同步游标、变更序号和失败重试队列。
- 服务端不能只依赖客户端时钟；使用服务端版本/序号帮助识别变更。
- 对冲突保留可恢复路径，不要静默丢弃用户数据。
- NAS 暂时离线时，客户端将本地变更放入待同步队列，连接恢复后继续处理。
- 局域网地址可以手动配置；自动发现是辅助能力，不得成为唯一连接方式。

### 7.3 私密内容的同步规则

快速隐藏、私密书架、设备授权和文件加密是不同概念： -
快速隐藏只处理屏幕呈现。 - 私密书架处理应用内的可见性与访问控制。 -
文件加密保护静态数据，需要明确密钥管理方式。 - 设备授权控制谁能访问
NAS。

私密书籍同步前必须有明确设置；不能把"隐藏"当成加密，也不能假定家庭 Wi-Fi
上的设备都可信。

## 8. 建议的 API 结构

统一使用版本化路径 `/api/v1`。以下是初步设计，实施时应根据真实用例调整。

---

方法与路径 作用

---

`GET /api/v1/health` 服务健康检查

`POST /api/v1/devices/pair` 设备配对

`GET /api/v1/devices` 查询已授权设备

`GET /api/v1/library/items/{id}/resources/{resourceId}` 获取封面、章节资源或漫画页面

`POST /api/v1/import-tasks` 创建导入任务

`GET /api/v1/import-tasks/{id}` 查询任务进度

`POST /api/v1/import-tasks/{id}/retry` 重试失败任务

`POST /api/v1/import-tasks/{id}/confirm` 确认元数据并入库

`GET /api/v1/providers` 查询已启用的来源适配器

`GET /api/v1/sync/changes?cursor=...` 获取增量变更

`POST /api/v1/sync/ack` 确认已应用的变更

认证、错误码、分页、幂等性、取消任务、上传接口和请求大小限制需要在 API
详细设计中补充。API 不能直接暴露 NAS 任意文件系统路径。

## 9. 安全与可靠性要求

### 9.1 网络与认证

- 第一版只要求家庭局域网使用，但仍必须有设备配对和认证。
- 不允许仅凭连接家庭 Wi-Fi 就访问书库。
- 优先使用安全传输；局域网也不是天然可信环境。
- 远程访问后续再启用，届时重新评估 TLS、身份认证、访问控制和暴露面。
- 日志不得泄漏密码、Token、Cookie、私密书名或完整敏感 URL 参数。

### 9.2 URL 导入与 SSRF 防护

NAS 代表用户访问 URL，必须防范 SSRF： - 默认拒绝
loopback、私有网段、链路本地、云服务元数据等不允许访问的目标。 - DNS
解析后和每次重定向后重新校验目标地址。 -
限制协议、重定向次数、下载大小、超时、并发数和速率。 - 不允许用户输入
URL 后访问任意 NAS 管理接口或内网服务。 -
来源认证信息应单独保存并限制权限。

### 9.3 文件和压缩包安全

- 不信任扩展名和来源声明。
- 防止 ZIP Slip/路径穿越、符号链接滥用、压缩炸弹和超大解压。
- 解压前后均执行大小、文件数、路径和资源限制。
- HTML 内容应清理脚本和危险外部资源。
- 转换器和解析器应限制
  CPU、内存、执行时间及文件访问范围；可使用隔离任务容器。
- 失败的解析/转换不能破坏原文件。

### 9.4 备份与恢复

- 数据库与书籍文件分开备份，但要提供一致性恢复流程。
- 记录数据库 schema 版本和迁移策略。
- 文档化恢复步骤，不能只提供"备份成功"状态。
- 删除作品前区分移除书库索引、删除设备缓存和删除 NAS
  原文件；危险操作需要确认。
- 重要变更应可追踪、可诊断。

## 10. 开发阶段与验收目标

### P0：本地阅读与 NAS 最小闭环

- 建立项目结构、代码规范、错误处理和基础测试。
- EPUB、TXT、PDF 阅读。
- CBZ/ZIP 和图片文件夹漫画阅读。
- 本地导入、格式识别、封面/目录提取和阅读位置保存。

## 11. AI 编程助手工作规则

所有 AI 编程助手在修改代码前必须遵守：

1.  **先检查仓库。** 阅读
    README、目录结构、现有代码、配置、测试和未提交变更；不要假设仓库是空的。
2.  **小步推进。**
    一次围绕一个可验证目标修改，说明准备改哪些文件和原因。
3.  **保护现有配置。**
    不擅自覆盖用户配置、删除数据、重置数据库、改网络设置或执行不可逆命令。高风险操作必须先询问并获得确认。
4.  **先计划再修改。** 对跨模块改动先给出简短方案、接口边界和验收标准。
5.  **保持分层。** UI 不直接绑定具体解析库；来源抓取不直接写
    UI；导入、解析、存储和同步各有清晰职责。
6.  **不伪造能力。**
    未实现的格式、同步、加密或来源不得标注为已支持。用测试样本验证后再宣称兼容。
7.  **新增依赖要有理由。**
    检查维护状态、许可证、平台支持、安全性、包体积与替代方案。
8.  **测试优先。** 为格式识别、进度序列化、冲突处理、导入安全和 API
    行为添加测试；运行与改动范围相关的测试并报告结果。
9.  **数据库变更可迁移。** 使用版本化 migration，避免直接破坏已有数据。
10. **安全默认值。** 不把密钥写进源码，不记录凭据，不允许任意
    URL/文件路径访问，不默认同步私密内容。
11. **尊重平台差异。** 桌面与移动端可以共享类型和业务逻辑，但不强求 UI
    或系统能力完全一致。
12. **说明未完成项。**
    结束时列出改动、验证、限制、风险和建议的下一步；不要只说"完成了"。

## 12. 当前明确决策与未决事项

### 已确认

- 产品名：**BookVault**。
- 产品是小说与漫画阅读器，包含桌面、移动和 NAS 服务端。
